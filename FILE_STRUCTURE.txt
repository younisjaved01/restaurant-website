====================================================================
COMPONENT ARCHITECTURE
====================================================================

Server Components (no client JS):
  app/layout.tsx, app/page.tsx

Client Components ('use client', use Motion and/or state):
  Navbar, Hero, Menu, Features, Testimonials, CTA, Footer

Data flows one direction: lib/data.ts -> components (props-free imports,
no global state, no context providers needed).

====================================================================
DATA ORGANIZATION
====================================================================

lib/data.ts exports three static, typed collections:
  - menuCategories: { sushi: MenuItem[], donburi: MenuItem[], juices: MenuItem[] }
  - testimonials: Testimonial[]
  - features: Feature[]

To update the menu, prices, hours copy, or testimonials, edit this file and
redeploy — no database or CMS is involved.

====================================================================
STYLING APPROACH
====================================================================

- Tailwind CSS utility classes directly in JSX for layout/spacing/color
- A small set of reusable component classes defined once in globals.css
  (@layer components): .btn-primary, .btn-secondary, .card-shadow
- Brand colors defined in tailwind.config.ts: primary (#dc2626),
  primary-dark (#991b1b)
- No CSS-in-JS, no separate stylesheets per component

====================================================================
TYPE SAFETY
====================================================================

- tsconfig.json: strict: true, no implicit any
- lib/data.ts defines MenuItem, MenuCategories, MenuCategoryKey,
  Testimonial, Feature interfaces/types used throughout
- lib/motion-config.ts uses `as const` on transition objects with literal
  union fields (ease, type: 'spring') so they satisfy Motion's Transition
  type instead of widening to `string`

====================================================================
PERFORMANCE INFO
====================================================================

- Fully static route, prerendered at build time (next build)
- whileInView animations run once (viewport: { once: true }) — no repeated
  reflows on re-scroll
- Animations use transform/opacity only (GPU-accelerated)
- First Load JS ~132 kB for the home route (Motion + React + app code)

====================================================================
CUSTOMIZATION GUIDE
====================================================================

Change menu items / prices:        lib/data.ts -> menuCategories
Change testimonials:                lib/data.ts -> testimonials
Change "Why Choose Us" cards:       lib/data.ts -> features
Change brand color:                 tailwind.config.ts -> colors.primary
Change hero copy/CTAs:              components/Hero.tsx
Change address/phone/hours:         components/Footer.tsx
Change animation timing/easing:     lib/motion-config.ts
Add a new page:                     add a folder + page.tsx under app/

====================================================================
TROUBLESHOOTING
====================================================================

- Mobile menu doesn't cover the full screen: check that no ancestor of the
  Navbar's fixed-position elements has a CSS filter/backdrop-filter/transform
  — any of those create a new containing block that clips `position: fixed`
  children to the ancestor's own box instead of the viewport. (This exact
  bug was found and fixed during development — see IMPLEMENTATION.md.)
- Motion TypeScript errors on `ease`/`type` fields: add `as const` to the
  transition object in lib/motion-config.ts.
- Blank-looking animated sections during manual testing: scroll/entrance
  animations may still be running — wait for them to finish (usually well
  under 1 second) before judging the final rendered state.
